# AGENTS.md — 給幫使用者把 Hearby for Windows 接好的 AI（Claude Code、Codex、Cursor、任何 agent）

你正在幫一個人把 **Hearby**（會議紀錄，開源）在他的 Windows 電腦上接好。
目標只有一個：**他開會前按一下、開完會資料夾裡就有一份紀錄，而且你（他的 AI）讀得到那份紀錄。**
驗收＝這件事真的發生，不是「某個檢查通過」。全程不要動他的其他設定、不要刪東西、不要幫他填 API 金鑰。

這份檔隨 app 一起裝在 `%LOCALAPPDATA%\HearbyApp\current\AGENTS.md`，沒有原始碼倉也讀得到。

## 0. 第一件事：跑體檢（不要自己翻資料夾猜）

Hearby.exe 是視窗程式：在 PowerShell 裡要接 `| Out-Host`，PowerShell 才會等它印完。

```powershell
& "$env:LOCALAPPDATA\HearbyApp\current\Hearby.exe" --doctor --deep | Out-Host
```

七行：系統／麥克風／系統聲／聽打模型／整理方式／磁碟／資料夾。每一行「缺」對應下面一節。

## 1. 裝 app

- 從 GitHub Releases 下載 `Hearby-Setup.exe`，雙擊。不需要系統管理員權限，裝在 `%LOCALAPPDATA%\HearbyApp`，開始功能表與桌面各一個捷徑。
- 安裝檔沒有數位簽章：Windows 會跳「Windows 已保護您的電腦」→ 按「其他資訊」→「仍要執行」。這一步只有他本人能按。
- 打開後 app 走四頁精靈：歡迎（背景下載聽打模型，約 0.6 GB）→ 讓它聽得到 → 紀錄要誰寫 → 試一次。可以陪他走。

## 2. 權限：Windows 不會跳視窗問，只有一個開關

| 項目 | 何時需要 | 怎麼開 |
|---|---|---|
| 麥克風 | 必要 | 設定 › 隱私權與安全性 › 麥克風：「麥克風存取」與「讓傳統型應用程式存取您的麥克風」都要開（`ms-settings:privacy-microphone`） |
| 電腦裡的聲音 | 只有「線上會議」情境 | 不需要任何權限（Windows 的 loopback 錄音） |

## 3. 整理方式：優先用他已經有的訂閱，不用 API 金鑰

| 順位 | 條件 | 怎麼接 | 怎麼驗 |
|---|---|---|---|
| 1 | 有 Claude 訂閱 | 精靈第 2 頁或設定「交給我的 Claude 整理」→ app 用官方指令裝 Claude Code（`irm https://claude.ai/install.ps1 \| iex`，不用管理員）、開瀏覽器登入；網頁給代碼就貼回 app | `& "$env:USERPROFILE\.local\bin\claude.exe" auth status` 有 `"loggedIn": true` |
| 2 | 自己裝了 Ollama／LM Studio | 設定「交給本機模型整理」→ 讀取模型 → 選一個 → 存 | 設定頁那列是「可以用」 |
| 3 | 都沒有 | 「先只要逐字稿」：有分段、時間戳，不用帳號 | 錄一段出 md |

ChatGPT（Codex）在 Windows 版還沒開放：macOS 版把它關在外層沙箱裡跑，Windows 上還沒有同等的做法。
登入永遠走官方 CLI 自己的流程；app 不做登入畫面、不收帳密（`COMPLIANCE.md`）。

## 4. 紀錄在哪、你怎麼讀

`%USERPROFILE%\Hearby\` 就是專案：`CLAUDE.md`／`AGENTS.md` 是入口，`memory\` 五個檔是他的會議記憶（設定裡打開「記憶」才會寫），`會議\<日期_時間_標題>\` 是每一場。
在那個資料夾打開你自己，第一句就能講出上一場的三個待辦。討論完的新決定寫回 `memory\THREADS.md`、待辦寫進 `OPEN.md`；
他手改過的行不要動、不確定的標 `[[?]]`、不要發明他沒說過的話。
你直接改了一場紀錄的 md（例如把人名改對）：跑 `& "$env:LOCALAPPDATA\HearbyApp\current\Hearby.exe" --memory-rebuild <那份 md> | Out-Host`，
那一場在 MEETINGS／OPEN／PEOPLE／index.json 的行會跟著換成新版；他改過的行不動，改之前留 `<檔名>.bak-日期`。這一場在那四個檔裡的段落不用自己改（自己改過的行，之後就不再跟著紀錄更新）。
要改一場的標題：**不要自己改 `會議\` 裡的資料夾名或檔名**（一場的 id＝主紀錄的檔名，記憶裡的路徑與 id 會斷）。在 Hearby 的紀錄清單把滑鼠移到那一場按筆（或按右鍵「改標題…」），
或跑 `& "$env:LOCALAPPDATA\HearbyApp\current\Hearby.exe" --rename <那份 md 或那一場的資料夾> "<新標題>" | Out-Host`：資料夾（日期時間不變）、夾裡以舊名開頭的檔、紀錄表頭的標題與音檔路徑、meta.json、
記憶裡這一場的 id（index.json、MEETINGS、OPEN、PEOPLE，還有 THREADS 等檔裡提到的；改之前留 `.bak-日期`）、副本資料夾，一起換。資料夾已經被人改過名的，照資料夾的標題跑一次就補齊。
想讓 Hearby 整理時認得他圈子裡的人名、案子：放一份 `memory\ROSTER.md`（名冊）。一行一個 `- 正名｜別名、簡稱｜常被聽錯的寫法｜是誰／什麼｜讀音`（後面幾欄可空；寫法後面加「（看上下文）」＝一般詞或不只一個人），`## ` 分節隨意，太長只帶前面 1.2 萬字（常出現的寫前面）。
有名冊（而且記憶是開的）時，整理會議會多帶名冊、THREADS 裡已定案的事、OPEN 裡還沒完成的待辦：名字照名冊寫，AI 另外列出逐字稿哪幾行的哪個字聽錯了，Hearby 只改那幾行裡的那個字、沒把握的在紀錄標 `[[?]]`，紀錄表頭多一行「> 名字更正：」寫改了什麼；已定案的不再列成開放問題、同一條待辦不重複開。沒有名冊＝跟以前一樣。本機模型不帶名冊。
改過的名字會記進 `memory\NAMES.md`（名字確認帳）：在 Hearby 裡自己改紀錄、重新整理時寫的「A」應為「B」、你改了紀錄後跑 `--memory-rebuild <那份 md>`（改之前要留 `.bak`，才找得到改之前那一版）。一行一筆 `- 聽到 → 正名｜換法｜誰改的｜日期｜哪一場`；換法「一律」＝別場逐字稿沒出現過、聽打完直接換，「看上下文」＝交給 AI 看上下文，「不換」＝不是聽錯；可以直接改或自己加一行。AI 沒把握的名字放在「要確認」（紀錄頁也有「是／不是」可以按），答一次就不再問。
想讓整理時知道「事情做到哪」：放一份 `memory\STATE.md`（現況）。四節——`## 案子`（`- 案子｜負責｜現況｜下一步｜期限`）、`## 還沒完成的待辦`（`- 事項｜負責人｜期限｜哪一案`）、`## 最近定案`、`## 還沒定的事`（`- 日期｜事情`），重要的寫前面（太長從後面截）。有這份時，待辦與定案用它的（不用 `OPEN.md`、`THREADS.md`），AI 也看得到案子現況與還沒定的事。
帶著記憶整理時，紀錄多一節「## 之前的事」：帶進來的待辦、案子、還沒定的事，這場有講到的，一件一行「- 事情 → 這場怎麼了 [mm:ss]」（沒有時間戳的不留）。寫「做完／不做了」的，記憶同步時把 `memory\OPEN.md` 裡別場那一條打勾（先留 `.bak`）。
讀音比對：帶著名冊整理時，Hearby 先照讀音把逐字稿裡唸起來像名冊名字、字卻不一樣的地方挑出來（「隱形」像「尹馨」；翹舌、ㄣㄥ、ㄌㄋ、送氣不分，不看聲調；原字有「的、是、有、一…」的不列，名冊第三欄已經寫的不列），名冊越前面的越先、最多 60 組，當候選交給 AI 看上下文決定——Hearby 自己不照它改字。AI 把字改成名冊名字的簡稱（「亞特」之於亞特蘭提斯）時，原字要唸起來像它才改。名冊第五欄的讀音寫成「字＝注音」（例：`藏＝ㄗㄤˋ`），會蓋過預設讀音（多音字）。拼音表 `PinyinData`（Mac 與 Windows 同一份）由 Mac 上的 `swift scripts/gen-pinyin.swift` 產生（`PinyinData.cs` 與 Swift 那份同時寫出），不要手改。
認聲音（說話人分段＋聲紋）只有 macOS 版：Windows 的整理不帶聲紋標籤（跟 Mac 版沒開認聲音時一樣），合約夾具也不含這一段。

設定、模型、錄音工作檔在 `%LOCALAPPDATA%\Hearby\`；紀錄檔在 `%LOCALAPPDATA%\Hearby\Logs\hearby.log`。

2. `%USERPROFILE%\Hearby\會議\` 多出一個夾，裡面有 `.m4a` 與 `.md`。
3. 你在 `%USERPROFILE%\Hearby\` 讀得到那份 md。
